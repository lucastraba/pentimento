# Polishing the review loop

> Comments were saved correctly but gave no sign of it, agents wrote in a recognizable AI register, and the page had three different column widths. This plan fixed all three, in six steps that have now shipped.

## The problems <!-- id: framing -->

An agent writes a plan, the reader leaves comments, and the agent revises. Before this work, both halves had a problem the tool did nothing about.

Saving a comment showed nothing. The form closed, the page reloaded, and the comment appeared in a collapsed panel at the top of the page, usually out of view. Storage worked (`test/comments.test.ts` covers it), but a reader had no way to tell.

Agents also wrote in the default AI register: "leverage", "robust", "isn't just X, it's Y", lists of bullets with bold labels. `pentimento guide` is what every agent reads before writing, and it said nothing about prose.

The layout had no single column width. Paragraphs wrapped at 68 characters, findings and tables ran to 90, and diffs extended to 150, so one page had three right edges.

## Where the comment flow failed <!-- id: today -->

Selecting text showed a button. Clicking it opened a form fixed to the bottom of the window, away from the selection. On Save, the form closed straight away (`assets/viewer.js:102`), the `meta.yml` write triggered the file watcher (`src/viewer.ts`, 200 ms debounce), and the page reloaded. The comment ended up in the header panel (`src/render.ts`, `commentsPanel`), and it might or might not get a highlight.

Failures were handled worse. `post()` never checked `response.ok`, so a 400 or 404 closed the form and lost the comment without a message (`assets/viewer.js:98-103`). A network failure left the form open with a Save button that did nothing. Any `.md` or `.yml` change reloaded the page, so an agent saving a snapshot erased whatever the reader was typing.

Highlights often failed too. The viewer wrapped the quote with `range.surroundContents` inside a try/catch (`assets/viewer.js:23`), which throws when a selection crosses an element boundary such as a bold phrase, a link, or two paragraphs. The error was swallowed and the comment got no highlight. The `prefix` and `suffix` context stored with each comment (`src/core.ts`, `CommentEntry`) was never used for finding the quote again. When a highlight did appear, the comment text was only in a tooltip.

::: findings
- CRIT :: A non-2xx save response closed the form and discarded the comment with no message, because `post()` in `assets/viewer.js` never checked `response.ok`.
- HIGH :: Nothing acknowledged a save where the reader was looking. The form closed, the page reloaded, and the comment appeared in the header, usually off screen.
- HIGH :: Any file change reloaded the page, so an agent's snapshot erased a comment the reader was still typing.
- HIGH :: Selections that crossed element boundaries got no highlight; `surroundContents` threw and the error was swallowed (`assets/viewer.js:23`).
- MED :: Resolving had no confirmation or undo, and resolved comments could not be seen in the viewer.
- MED :: Comment counts appeared nowhere: not in the viewer bar and not on the index page.
- MED :: Comments could not be edited or deleted without editing `meta.yml` by hand.
@collapse Lower-severity gaps
- LOW :: Selections over 600 characters hid the comment button without explanation (`assets/viewer.js:66`).
- LOW :: Only `mouseup` showed the button, so keyboard and touch selections never did.
- LOW :: Old revisions disabled commenting with no explanation (`canComment: !rev`).
- LOW :: The form had no keyboard shortcuts: Esc did not cancel and ⌘Enter did not save.
:::

## Changes to commenting <!-- id: comments -->

### Saving <!-- id: save-moment -->

When the reader presses Save, the browser still has the selected range, so the viewer highlights it right away with the CSS Custom Highlight API. The highlight works across element boundaries and doesn't change the DOM. The server response confirms it afterwards.

The Save button now reads Saving… and then Saved ✓ before the form closes. A small notice near the highlight shows the comment id and an Undo button. Undo deletes the comment through a new `POST /api/uncomment` endpoint, which covers most "that came out wrong" cases without an edit feature.

Failed saves keep the form open with the text in it and a one-line error. Drafts are saved to `localStorage` as the reader types, so a reload brings the form back with its text.

The form opens under the selection instead of at the bottom of the window. Esc cancels and ⌘Enter saves. Selections over 600 characters still get the button; the quote is cut to 600 characters and the form says so.

### Updates without reloading <!-- id: on-page -->

The server now sends two kinds of events. A comment event makes the page fetch the comment list and update highlights and the drawer. A document event makes the page fetch the new HTML and replace `<main>` and `<header>`, keeping the scroll position. If a comment form is open, the replacement waits until it closes. This removed the flash, the jump in scroll position, and the lost drafts.

A drawer replaced the header panel. A button in the viewer bar shows the open count and opens a side panel with open comments first and resolved ones below. Clicking a highlight opens its card, and clicking a card scrolls to its highlight. Resolving moves a card to the resolved list and offers Undo. The index page shows the count for each document.

We compared three ways to highlight:

| Approach | Crosses elements | Changes the DOM | Browser support | Notes |
|---|---|---|---|---|
| Single text-node search (before) | no | yes | all | fails on any styled selection |
| Wrapping each text node | yes | yes | all | the usual annotation-tool approach |
| CSS Custom Highlight API | yes | no | Chrome 105+, Safari 17.2+, Firefox 140+ | ranges survive page updates |

We chose the Custom Highlight API with no fallback. The browsers this viewer targets all support it, and because it leaves the DOM alone it works with the in-place page updates. The stored `prefix` and `suffix` now pick the right match when a quote appears twice.

### Seeing what happened to a comment <!-- id: round-trip -->

Before, a resolved comment just disappeared from the list. Now its card says "resolved in r003" and links to the r002 to r003 diff, so the reader can check what their comment changed.

Replies are for comments that need an explanation rather than a change to the document. The agent runs `pentimento reply <id> --text "..."`, and the reader can reply from the card. Replies are one level deep and plain text. `address` prints them, and `resolve` accepts `--note` to close a comment with a reply.

On an old revision, selecting text shows a note saying the revision is read-only, with a link to the current version.

## Prose rules for agents <!-- id: prose -->

The skill tells agents to run `pentimento guide`, which prints instructions from the installed CLI. Anything added there reaches every agent on every install, so that is where the prose rules went.

The guide gained a "Prose" section with about ten rules: plain words instead of promotional ones, "is" instead of "serves as", no "isn't just X, it's Y", no rhetorical openers, bullets written as full sentences, specific references, one hedge per claim, and varied sentence length. A separate page, `pentimento guide style`, shows the rules applied to each archetype.

`pentimento lint` checks the mechanical signs: a list of promotional words, false-contrast patterns, stock openers, bold-label bullets, em-dash density, and emoji in headings. It reports line numbers, and `--strict` exits with an error for CI. `snapshot` prints the warning count so the agent sees it before the reader does. Lint can't judge whether a document is well organized, so the guide still does most of the work.

## One column width <!-- id: measure -->

In `assets/theme.css`, the container was 90 characters wide (`.wrap`, line 43), paragraphs were capped at 68 (`p`, line 50), and list items at 66. Findings, tables, timelines, callouts, and the verdict grid used the full 90. `::: diff` widened to 150 characters and was centered.

The diff was the only wide element that looked intentional, because it was centered on the column. We applied the same approach everywhere. The container is now the prose width, about 70 characters, and everything uses it by default. Side-by-side diffs, wide tables, and figures widen symmetrically using one shared width setting.

This changed only `theme.css`, so every existing document picked it up on its next render. It also removed the per-element `max-width` rules, which means a new component gets the right width without extra CSS.

## Decisions and order of work <!-- id: recommendation -->

::: callout decision id=d-trust-first
**Make saving reliable before adding features, and ship the independent pieces first.** Button states, the immediate highlight, and error handling answer "did my comment save?" without the drawer, in-place updates, or replies. The width fix and the prose rules don't touch the viewer and could ship on their own. We kept the viewer as a single script with no framework.
:::

::: callout decision id=d-review-round
**Decided in the first review.** The viewer is for one person on their own machine, so undo and delete are limited to comments made in the current browser session, with no accounts. The static render keeps its header panel. Highlighting uses the Custom Highlight API only. Replies stay one level of plain text. Lint was to wait until the prose rules proved insufficient; it shipped later, and it warns without blocking a snapshot.
:::

::: timeline
1. **One column width** [done] — `theme.css` only: the container becomes the prose width, per-element limits go, and wide elements widen symmetrically.
2. **Prose rules** [done] — The guide's Prose section and the `pentimento guide style` page.
3. **Reliable saving** [done] — Immediate highlight, Save button states, error handling that keeps the text, saved drafts, keyboard shortcuts, the form under the selection, and a count in the viewer bar.
4. **No more reloads** [done] — Separate comment and document events, in-place updates, and waiting while a form is open.
5. **The drawer** [done] — Open and resolved lists linked to highlights, resolve with undo, links to the diff that resolved a comment, deleting your own comments, and counts on the index page.
6. **Replies and remaining gaps** [done] — One-level replies with `pentimento reply` and `resolve --note`, keyboard and touch selection, and a note on read-only revisions.
:::
