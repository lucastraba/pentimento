# Polishing the review loop

> Pentimento fixes every pixel of the page but not the moment that matters most: the second after you press "Save comment".

## Framing <!-- id: framing -->

The review loop is the product. An agent writes a plan, a human reads it and leaves comments, the agent revises against them. Both halves of that loop have a quality gap the tool doesn't police today.

The first gap is trust. Saving a comment gives no evidence anything happened: the form vanishes, the page reloads, and the comment lands in a collapsed panel at the top of a page you're 60% scrolled into. Every save feels like dropping a letter into a mailbox with no slot — you let go and hope. The mechanics are correct (`test/comments.test.ts` covers the storage round trip), but correct and trustworthy are different properties, and the viewer only delivers the first.

The second gap is prose. `pentimento guide` is the version-matched source of truth every agent reads before authoring, and it says nothing about how to write. So agents produce plans in default AI register — "leverage", "robust", "isn't just X — it's Y", bullet walls with bold leads — inside a page whose typography promises better. The tool that owns every pixel should also own the register.

The third gap is the page itself: the layout has no single measure. Prose wraps at one width, findings and tables run wider, and diffs break out wider still — three right edges on one page, none of them looking deliberate.

This document walks the loop as a reader experiences it, catalogs where it breaks, and proposes directions for all three.

## Where the loop breaks today <!-- id: today -->

Walk it end to end. You select a sentence mid-document; a floating button appears; you click it and a form opens — fixed to the bottom center of the viewport, disconnected from your selection. You type, press Save, and three things happen in sequence: the form removes itself immediately (`assets/viewer.js:102`), the `meta.yml` write wakes the file watcher (`src/viewer.ts`, 200ms debounce), and the SSE snippet runs `location.reload()`. What you see: the form blinks away, the page flashes, and nothing where you were looking acknowledges the comment. It did save — as a highlight you may or may not get (see below) and as an entry in the `<details class="comments">` panel rendered into the page header (`src/render.ts`, `commentsPanel`), off-screen at the top.

The failure paths are worse than the success path. `post()` never checks `response.ok`, so a 400 or 404 resolves normally and the form still removes itself — the comment is silently gone (`assets/viewer.js:98-103`). A network-level failure rejects the promise, so `form.remove()` never runs — the form stays open, the button goes dead, and no message explains either state. And because any `.md`/`.yml` change under the served root triggers the reload, an agent snapshotting while you type destroys your half-written draft.

Highlighting is best-effort in a way that fails often. The quote search walks text nodes and calls `range.surroundContents` inside a try/catch (`assets/viewer.js:23`); any selection that crosses an element boundary — a bold phrase, a link, two paragraphs — throws, the catch swallows it, and the comment gets no mark at all. The `prefix`/`suffix` context captured in the W3C-annotation style (`src/core.ts`, `CommentEntry`) is stored and shipped to `address`, but the viewer never uses it for anchoring. Even a successful mark is inert: the comment text lives in a `title` tooltip, the mark isn't clickable, and nothing links marks to panel entries.

::: findings
- CRIT :: A non-2xx save response removes the form and discards the comment with no message — `post()` in `assets/viewer.js` never checks `response.ok`.
- HIGH :: No acknowledgment at the point of interaction: save = form vanishes + full page reload; the saved comment renders off-screen in the header panel.
- HIGH :: Any file change reloads the page, destroying an in-progress comment draft — the agent snapshotting mid-review wipes the reader's typing.
- HIGH :: Selections crossing element boundaries (bold, links, multiple paragraphs) get no highlight; `surroundContents` throws and the error is swallowed (`assets/viewer.js:23`).
- MED :: Resolve is a bare POST with no confirmation and no undo; the entry disappears on the next reload and resolved comments have no view in the viewer at all.
- MED :: No comment counts anywhere — not in the vbar, not on the index cards; the header panel only exists when open comments exist.
- MED :: No edit or delete: a typo in a comment lives in `meta.yml` until someone hand-edits YAML.
@collapse Lower-severity gaps (4)
- LOW :: Selections over 600 characters silently suppress the comment button (`assets/viewer.js:66`) — no explanation offered.
- LOW :: `mouseup` is the only trigger; keyboard and touch selections never see the button.
- LOW :: Viewing an old revision silently disables commenting (`canComment: !rev`) — selection just does nothing, with no hint why.
- LOW :: No keyboard support in the form: Esc doesn't cancel, ⌘Enter doesn't save.
:::

## Ideas: the comment interface <!-- id: comments -->

Three moments need work, in order of how much they hurt: the save, the reading experience with comments present, and the round trip back from the agent.

### The save moment <!-- id: save-moment -->

The fix for "comments disappear" is to make the acknowledgment happen where the reader is looking, before the server round trip completes.

Highlight the selection optimistically at save time. This is the load-bearing idea: at the moment Save is pressed, the live `Range` is still available, so the client registers it with the CSS Custom Highlight API immediately — no DOM mutation, and it works across element boundaries, unlike the post-reload single-node text search. The highlight appears under your cursor the instant you save; the server write and the SSE event just confirm what you already see.

Give the button states: Save → Saving… → Saved ✓, then close. Follow with a small toast anchored near the new mark: "Saved c-2026-07-09-001 · Undo". Undo deletes the comment (needs a `DELETE`/`POST /api/uncomment` endpoint) — cheaper than an edit feature and covers the "wait, that came out wrong" case.

Make failure loud and lossless. Check `response.ok`; on any failure keep the form open with an inline one-line error and the text intact. Persist drafts to `localStorage` keyed by document + quote as the reader types, so even a hostile reload restores the draft into a reopened form.

Attach the form to the selection instead of the viewport bottom — a popover under the highlight, like every annotation tool readers already know. Add Esc to cancel and ⌘Enter to save. For selections past the 600-character cap, show the button anyway and truncate the quote with a visible note, instead of silently refusing.

### Living with comments on the page <!-- id: on-page -->

Kill the full reload. Type the SSE events instead of one generic "reload": a `comment` event carries the entry and the client patches in place (add or remove a mark and a card); a `document` event fetches the new HTML and morphs `<main>` and `<header>` in place, preserving scroll position, open forms, and selection. If a comment form is open when a document event arrives, defer the morph until it closes. This one change removes the flash, the scroll jump, and the draft destruction in a single move.

Replace the header panel with a drawer. A fixed toggle in the vbar with a live count ("💬 3") opens a right-side drawer listing open comments first, resolved below, each card showing quote, text, author, date. Cards and marks link both ways: click a mark to open its card, click a card to scroll to and flash its mark. Resolve moves the card to the resolved group with an undo toast instead of deleting it from view. The index page gets the same count as a chip per document card.

Pick a highlighting strategy deliberately. Three candidates:

| Strategy | Cross-element | DOM mutation | Support | Notes |
|---|---|---|---|---|
| Single-node text search (today) | no | yes | all | fails on any styled selection |
| Multi-node mark wrapping | yes | yes | all | wrap each text-node slice; standard annotation technique |
| CSS Custom Highlight API | yes | none | Chrome 105+, Safari 17.2+, Firefox 140+ | cleanest; ranges stay live across morphs |

Decided in review: the Custom Highlight API, alone. Every browser this is for already ships it, and a second code path buys nothing. It also pairs well with DOM morphing, since it never mutates the tree it highlights. Use the stored `prefix`/`suffix` for re-anchoring when a quote appears twice or the text shifted — the data model already carries what the viewer ignores.

### The round trip <!-- id: round-trip -->

The reader's comment goes to the agent through `pentimento address`; the agent revises, snapshots, and resolves. Today the reader sees the resolution only as absence — the comment stops being listed. Close the loop visibly: a resolved card reads "resolved in r003" and links the r002→r003 diff page, so the reader can check what their comment actually caused.

One level of replies would carry the cases where the answer isn't a revision: `pentimento reply <id> --text "left as is — the constraint is deliberate"` from the agent, and a reply box on the card for the reader. `address` prints threads; `resolve` gains an optional `--note`. Worth doing only after the drawer exists, one level deep, and only if it stays a text field and a list — the moment it wants editing, notifications, or its own state, it gets dropped. This is a review tool, not a forum.

When viewing an old revision, say why commenting is off: a line in the vbar — "viewing r002 · read-only — comments attach to the current version" — with a link back to canonical.

## Ideas: prose without slop <!-- id: prose -->

The distribution channel already exists. The skill shim defers to `pentimento guide`, which prints version-matched instructions from the installed CLI — so a style ruleset added there reaches every agent (Claude Code, opencode, Codex) on every install, with zero per-user configuration. Three layers, from teaching to enforcement:

**Teach.** Add a "Prose" section to the main guide: roughly ten hard rules an agent can follow mechanically. Plain words over promotional ones (use, reliable, smooth — never leverage, robust, seamless, delve, streamline). "Is" and "has", not "serves as" and "boasts". No false contrast ("it isn't just X — it's Y" and its split variants). No engagement hooks or rhetorical-question openers. Bullets are full claims with verbs and numbers, not bold-lead fragments. Specific citations over vague sweep; one hedge per prediction; sentence lengths that vary. Ten lines in the guide buys a register shift in every document authored after it ships.

**Show.** A `pentimento guide style` deep page with before/after pairs per archetype — a slop verdict cell next to a clean one, a bold-lead bullet list next to prose that says the same thing. Agents imitate examples better than they obey rules; the archetype skeletons in `pentimento guide archetypes` could each carry one line of register guidance too ("a senior engineer's memo, not a launch post").

**Enforce.** `pentimento lint <doc>`: mechanical tells only, so the tool stays honest about what it can detect. Banned-word list with line numbers, false-contrast regexes, "Here's the thing"/"The catch?" hooks, bold-lead bullet ratio per list, em-dash density per thousand words, emoji in headings, "In today's" openers. Plain output, `--strict` exits nonzero for CI. Then wire it into the moment that matters: `snapshot` prints a one-line warning when the document has lint findings ("4 style warnings — run `pentimento lint Plan.md`"), so the agent sees it exactly when it's about to publish and revises before the reader ever reads slop. Rules live as data in a new `src/lint.ts`; the guide's loop step gains "lint before snapshot".

Detection has limits — a linter catches vocabulary and syntax tells, not structural blandness — which is why it's the third layer, not the first. The guide teaches the register; lint catches the regressions.

## Ideas: one measure <!-- id: measure -->

The numbers in `assets/theme.css` tell the story. The container is 90ch (`.wrap`, line 43), but paragraphs cap at 68ch (`p`, line 50) and list items at 66ch — while findings (`.finding > div { max-width: none }`), tables (`width: 100%`), timelines, callouts, and the verdict grid all run the full 90ch. On a wide screen the page alternates between a 68ch prose rag and 90ch blocks, and `::: diff` adds a third width by breaking out to `min(150ch, …)` centered. Three right edges, and the wide ones read as accidents because they share the prose column's left edge and nothing marks them as featured.

The diff block already contains the answer: it breaks out *symmetrically*, centered on the column with the `translateX(-50%)` pattern, which is why it looks intentional where the findings just look wider. Generalize that into a two-width system. The wrap becomes the prose measure — 70ch or so — and every element inherits it by default, so paragraphs, findings, callouts, timelines, and the verdict grid all share one column and one right edge. Components that genuinely need room — side-by-side diffs, wide tables, figures — become deliberate centered breakouts using the pattern the diff established, sized by a single shared token instead of per-component numbers. One column for reading, one wider stage for exhibits, nothing in between.

This is a theme-only change: `theme.css` is the entire visual surface, so no document ever changes and every existing render picks up the fix. The redlines are the per-element `max-width` overrides — once the wrap is the measure, `p { max-width: 68ch }`, `li { max-width: 66ch }`, and the scattered `max-width: none` escapes can all go, which is the real win: the current system needs every new component to remember its width, the proposed one makes consistency the default.

## Recommendation <!-- id: recommendation -->

::: callout decision id=d-trust-first
**Fix trust before features, and ship the independent tracks first because they're cheap.** The complaint is "did my comment save?" — answered by button states, an optimistic mark, and lossless error handling, none of which need the drawer, morphing, or threads. The measure fix (theme only) and the prose work (guide section + lint) touch no viewer code and can land in the next release. The drawer and replies are the polish tier; they only pay off once the save moment is trustworthy. This forecloses a bigger rewrite (framework, virtual DOM) — the viewer stays one dependency-free script, budgeted to grow from ~105 to a few hundred lines.
:::

::: callout decision id=d-review-round
**Decided in the first review round.** Identity stays trivial — this is personal, local use, so a per-session token scoping undo and delete is enough. The static render keeps its header panel; drawer parity waits until sharing matters. Highlighting uses the CSS Custom Highlight API with no fallback path. Replies are approved conditionally: one level, a text field and a list, dropped if they grow. Lint is on hold — the guide's prose rules and style page ship first, and lint gets built only if slop still gets through; if it ever ships, it warns and never gates a snapshot.
:::

::: timeline
1. **One measure** [done] — `theme.css` only: the wrap becomes the ~70ch prose measure, per-element `max-width` overrides go away, wide components (diffs, figures) become deliberate centered breakouts sized by one shared token. Every existing document picks it up on next render.
2. **Prose rules** [done] — Guide "Prose" section and `pentimento guide style` page with before/after pairs. No viewer changes; shipped alone. Lint waits for evidence the guide isn't enough.
3. **Trust the save** [done] — Optimistic highlight from the live selection (Custom Highlight API), Save→Saving→Saved states, `response.ok` checks with inline errors that never drop text, localStorage drafts, Esc/⌘Enter, selection-anchored form, comment count in the vbar.
4. **Kill the reload** [done] — Typed SSE events; comment events refetch and patch in place, document events morph `<main>`/`<header>` preserving scroll and open forms; morph deferred while a form is open.
5. **The drawer** [done] — Open and resolved lists with highlight↔card linking, resolve with undo, "resolved in rNNN" diff links, delete-own-comment, count chips on the index page.
6. **Polish tier** [done] — One-level replies with `pentimento reply` and `resolve --note`, selection capture via `selectionchange` (keyboard and touch included), revision read-only notice in the bar.
