# Vellum v1 — Living Plans

> Plans are markdown, versioned in place, rendered to constrained HTML. The agent writes content; the system owns the pixels.

## Why

Past attempts at HTML plans failed the same way: the agent was handed a paint palette. Slop UI, wasted medium, no consistency across plan types — all one disease. Vellum inverts it: a deterministic renderer, a fixed design system, and a directive vocabulary. Agents (this one or any other) produce markdown + directives; the toolchain produces the view.

Builds on `vellum-prd.md` (2026-05-14) — this plan is Chunks 4+5 of that PRD, fused with Claude Code plan mode, informed by the 2026-07-05 audit of Vellum Lite in Pandora.

## Locked decisions (2026-07-05)

- **Markdown is the source of truth.** HTML is a build product. Plan mode approves the markdown; the HTML is how Lucas reads it.
- **Dual delivery.** Every render writes a self-contained HTML file next to the plan (agent-portable). Claude additionally publishes it as a claude.ai Artifact. The local viewer (Phase 2) serves the same files — if it works well, it becomes publishable as a product.
- **Four archetypes in v1:** implementation plan, brainstorm/exploration, audit/review, design doc/PRD.
- **Read-only v1, comment-ready architecture.** Anchored comments (Antigravity-style plan review) are Phase 3, but every rendered block gets a stable anchor id from day one, and `meta.yml` reserves the `comments:` schema. Retrofitting anchors later would break old revisions.
- **Versioning is Vellum Lite in-repo:** `PLAN.md` + `.history/PLAN/rNNN.md` + `meta.yml` decision log. Pure filesystem. Pandora keeps the same convention, so one mental model.
- **The CLI is rewritten, not reused.** Audit verdict: the convention ports cleanly; the current CLI does not (Obsidian-CDP transport, history-overwrite bugs, lossy frontmatter round-trip).

## Architecture

```
PLAN.md ──▶ vellum CLI ──▶ plan.html ──▶ claude.ai Artifact (Claude publishes)
   │        (snapshot,          └───────▶ local viewer daemon (Phase 2, Tailscale-only)
   │         render)
   └──▶ .history/PLAN/rNNN.md + meta.yml (decisions, comments)
```

### vellum CLI v2 — TypeScript/Node

Commands: `snapshot`, `list`, `diff`, `revert`, `render`. Single package, runs via `npx`/bin. Fixes every audit finding by construction:

- Snapshot bumps `Current Revision` in the canonical atomically (audit C1); refuses to overwrite an existing `rNNN.md` (C1); `create` never clobbers without `--force` (C2).
- `History Folder` is canonical-relative, one contract everywhere (C3).
- `meta.yml` read/written with a real YAML library — no string-prefix matching, no injection (H2, M4).
- Frontmatter handled by a YAML-aware parser; round-trips lists and multi-line values (H3).
- `datetime.now().astimezone()` equivalent — no hardcoded UTC+2 (M1).
- Write-to-temp + rename for atomicity; lockfile per document (M3).

### Design system — `vellum.css` + tokens

- One stylesheet shipped by the skill. Both themes, token-level. Responsive by construction (desktop / iPad / iPhone).
- Archetypes share every component; each archetype sets an accent hue + badge so the plan's *kind* is legible at a glance.
- Hard rules: agents never write CSS, `style=""`, or JS. Interactivity (collapse, diff mode toggle, revision picker) is a fixed, skill-shipped snippet.

### Renderer — deterministic markdown → HTML

- `markdown-it` + container directives. The agent's whole expressive surface:
  - `:::callout info|warn|risk|decision` — callouts; decisions link to meta.yml entries.
  - `:::compare` — option comparison grid / decision matrix.
  - `:::timeline` — phases with status.
  - `:::findings` — severity-grouped findings (audit archetype).
  - `:::files` — file-touch table (implementation archetype).
  - `:::diff path=...` — fenced before/after blocks rendered side-by-side on wide screens, unified on narrow. Diffs are computed at build time; no client-side diff library.
  - ` ```mermaid ` — pre-rendered to inline SVG at build time (mmdc); never client-rendered (Artifact CSP forbids CDNs anyway).
- Every block gets a stable content-derived anchor id (comment substrate).
- The hand-built r001 artifact of this plan is the renderer's golden file: `vellum render PLAN.md` must reproduce it.

### The skill

`SKILL.md` teaching any agent the loop:

1. Enter plan mode; research as normal.
2. Pick the archetype; write `PLAN.md` following its skeleton (skeletons + a worked example per archetype ship as reference files).
3. `vellum snapshot` — drafts the what-changed/why decision entry.
4. `vellum render` — produces the HTML.
5. Publish: Artifact (Claude) or point at the viewer (other agents).
6. On feedback: revise markdown, snapshot, re-render — same URL, history accretes.

Optimized for Claude Code first; the CLI contract is what makes it portable to other agents later.

## Archetypes

| Archetype | Job | Signature components |
|---|---|---|
| Implementation plan | Approve-and-execute | phases timeline, file-touch table, diff views, risk callouts |
| Brainstorm / exploration | Compare directions | option cards, decision matrix, open-questions block |
| Audit / review | Report findings | severity-grouped findings, evidence links, verdict banner |
| Design doc / PRD | Record a vision | architecture diagrams, decision log, compare tables |

Flexibility = choosing the archetype and which sanctioned components to use. Consistency = everything else is fixed.

## Build order

- **Phase 1 — CLI core + design system + renderer + skill.** End state: this loop works end-to-end in any repo, publishing Artifacts. (This plan's r001 render is the golden file.)
- **Phase 2 — Local viewer.** Hono daemon, bound to Tailscale IP only (never 0.0.0.0 on nyx). Watches `.history/`, SSE hot reload, revision picker, diff pane. If it's good → productize.
- **Phase 3 — Anchored comments.** Click a block in the viewer → comment lands in `meta.yml`; `vellum address` has the agent read open comments, revise, snapshot, resolve. The Antigravity loop.
