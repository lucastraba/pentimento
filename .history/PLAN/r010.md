# Pentimento

> Pentimento keeps every draft of a markdown document and shows what changed between rounds and why. It serves two uses with one mechanism: a person revising their own writing, and an agent revising a plan from the person's comments.

## What it does <!-- id: why -->

A document is one markdown file that stays where it is. `pentimento snapshot` copies it into `.history/<name>/rNNN.md` and records a summary in `meta.yml`. When no summary is given, the snapshot writes one from the diff, using the document's headings ("Rewrote Chorus").

`pentimento serve` shows the current draft as a page. From the second draft on, the page offers the diff against the previous draft, a traces view with the previous draft showing under the current one, the passages cut in earlier drafts, and the full history. In the live viewer the reader can also step through drafts, comment on selected text, answer questions the agent asked, and approve a draft.

Agents use the same commands. `pentimento address` gives them the reader's open comments and answers, and `pentimento resolve` records which draft answered each one, which the page then shows next to the diff.

## Decisions <!-- id: decisions -->

::: callout decision id=d-source-of-truth
**The markdown file is the document, and history is plain files.** The HTML is always generated from it. Drafts and metadata sit in `.history/` as markdown and YAML, so grep, git, Obsidian, and agents can all read them. There is no database.
:::

::: callout decision id=d-vocabulary
**Documents don't control how they look.** Agents write markdown and a small set of `:::` directives; one stylesheet decides the rest. When a document needs something the directives can't express, the vocabulary changes in a release. This is what keeps agent output consistent from one plan to the next.
:::

Two more choices follow from these. Pentimento is built for one person and one document at a time: comments are that person's instructions to the agent, and there are no accounts, reviewers, or shared editing. When the agent runs on a remote machine, `--tailscale` gives the same person a private link to the viewer; it does not make the document shared.

The project was called Vellum until July 2026. Documents marked `Vellum: true` are still read and are migrated on their next snapshot.

## Settled in September 2026 <!-- id: settled -->

The Obsidian plugin will work inside Obsidian rather than open the browser viewer. For your own writing the point is to stay in the editor; the browser viewer stays the place for agent plans, comments, and approval. The plugin will write drafts through Obsidian's vault API instead of calling the CLI, so it also works on phones. That means moving the file access in `src/core.ts` behind a small storage interface first. The diff and traces code in `src/semdiff.ts` has no file access and can be shared as it is.

`::: figure` is out of the authoring guide. It still renders for older documents, and lint suggests `::: flow` for new ones. Flow arrows now take labels (`A -(writes)-> B`), which covers the diagrams figure was mostly used for.

Static renders embed the last 10 drafts and a scrubber in the header. `pentimento render --drafts all` embeds every draft and `--drafts 0` none. A four-draft song adds a few kilobytes; a long plan with 20 drafts would add several hundred, which is why the default is capped.

Obsidian syntax now renders as Obsidian shows it: `[[links]]`, `==highlights==`, `> [!note]` callouts, and footnotes, with `%% comments %%` hidden.

## Status <!-- id: shipped -->

Version 0.6 hardened rendering and paths, added the protected Tailscale mode, and set up CI across Node 20, 22, and 24 with a packed-install test. Version 0.7 added `::: flow`, checklists, option tables, and change marks in the contents. Version 0.11 replaced the six palettes with one quieter design, added traces, cuttings, computed summaries, the scrubber, approvals, `::: ask`, and Obsidian syntax, and rewrote the agent skill around a directive budget and example documents.
